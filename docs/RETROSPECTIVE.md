## 3. 로드맵 — 계획 기간 대비 실제

**총 18–20주로 추정했던 일정이 실제로는 코드 구현·테스트·문서화 자체는 단일
세션 안에 끝났다** — AI 페어 코딩이 "개발자 리소스"라는 시간 추정 전제 자체를
무너뜨린 사례다. 다만 이게 "일정을 이겼다"는 뜻은 아니다 — §6·§7 참고.

## 5. 계획에 없었지만 이번에 발견·추가된 것(초과 달성)

- **NF7(idempotency) 구현 갭 발견**: SPEC/ADR에는 결정돼 있었지만 v3 구현 당시
  실제 코드에는 없었다 — `grep`으로 확인 후 Phase 4에서 수정. 이건 "계획대로
  다 됐다"는 착각을 실제로 깬 유일한 사례다.
- **Gate A–G "불가능" 판단 자체가 틀렸다는 재발견**: `docs/LIMITS.md`에 처음
  "의존성 미통합으로 불가"라고 적었으나, 실제로 `agent-evaluator`가 PyPI 설치형
  패키지임을 뒤늦게 확인 — 판단을 뒤집고 실제로 배선했다.
- **배정 공정성 지표(`fairness.py`)**: SPEC엔 "Phase 4에서 지표"라고만 있었지
  구체 설계는 없었다 — 반려율 격차 계산 + 표본부족 자동 경고까지 이번에 설계.
- **`rbac-permission-audit` 스킬**: SPEC이 지목한 4개 후보 중 하나가 실제로
  3회+ 기준을 채워 스킬화됐다(나머지는 안 채워 스킬화하지 않음 — 이것도
  계획에 없던 "정직한 판단" 사례).
- **샌드박스 우회 방지 회귀 테스트(`test_gc38`)**: SPEC엔 명시돼 있지 않았지만
  Phase 4에서 "실패가 성공으로 둔갑하지 않는가"를 코드 레벨에서 증명하는
  테스트를 추가로 설계했다.

## 6. 계획했지만 못 하거나 보류한 것

- **Gate A–G 실측 실행**: 배선은 끝났지만 실제 실행은 사용자가 "나중에 직접"을
  선택해 보류. (비용이 안 들 가능성이 높다는 것까지는 밝혀뒀다.)
- **Docker 샌드박스 실제 격리 동작 검증**: 개발 환경에 Docker가 없어 원천적으로
  불가능했다.
- **2인 팀 실전 클레임 충돌**: 단독 세션이라 정의상 발생할 수 없다 — 시뮬레이션
  하면 거짓 증거가 되므로 하지 않았다.
- **Skills 3/4 후보**: 원칙4(3회+ 반복 확인)를 지키기 위해 의도적으로 스킬화
  보류.
- **GitHub 원격 연결, `release_hold`/`deploy` 승인**: 전부 사용자의 명시적 선택
  으로 보류 — 이 세션이 스스로 승인하지 않았다.
- **실제 AgentForge `spec_interpreter`/`code_generator`/`verifier` 연동**: F4의
  `default_stub_generator`는 여전히 스텁이다. Gate A/G가 의미 있는 점수를
  내려면 이 연동이 먼저 필요하다.

## 7. 한눈에 — 무엇이 계획과 가장 달랐나

- **"F1–F14를 순서대로 버전에 배정한다"는 계획은 거의 정확히 지켜졌다** — 유일한
  예외가 F9(계획상 v4, 실제로는 v3에서 이미 완성)다. 사소해 보이지만, 이건
  "계획 문서를 실행하면서도 계획 문서 자체가 최신 상태인지 계속 재확인해야
  한다"는 걸 보여준 사례다 — v4 착수 시점에 SPEC을 다시 읽지 않았다면 F9를
  중복 구현할 뻔했다.
- **가장 큰 반전은 Gate A–G였다.** "불가능"이라고 두 번(§7 로드맵 서술, LIMITS
  최초 버전)이나 문서화했던 항목이, 실은 몇 줄의 `pip install`로 끝나는
  일이었다 — 이건 "이 의존성은 별도 통합 작업이 필요하다"는 판단을 실제로
  검증하지 않고 넘겨짚었던 것이다. `agent-eval check`처럼 근거를 먼저 확인하는
  습관(evidence-based-gate-fix 스킬의 정신)을 이 프로젝트 자신에게도 더 일찍
  적용했어야 했다.
- **NF7(idempotency)이 실제로 빠져 있었다는 것도 같은 종류의 교훈이다** —
  "SPEC/ADR에 결정돼 있다"와 "실제로 코드에 구현돼 있다"는 다른 사실이고,
  Phase 4(검증) 단계를 실제로 밟지 않았다면 이 갭은 release_hold까지 조용히
  통과했을 것이다.
- **개발 자체의 "빠름"은 착시일 수 있다.** 42건의 골든셋이 전부 통과했다는 게
  "완성"을 뜻하지 않는다 — Gate A-G 미실행, Docker 미검증, 2인 협업 미검증이라는
  세 가지 실전 검증 축이 전부 이 세션의 범위 밖에 남아 있다. 이 회고 자체가
  그 경계를 정직하게 긋는 문서다.
