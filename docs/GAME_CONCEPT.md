# Gatekeeper — HAIR 협업 구조를 게임화한 웹 브라우저 게임

사용자 요청(2026-10-07, "HAIR로 AI가 적용되는 새로운 게임을 기획하고
동작 가능한 수준으로 개발 가능한지 분석해줘"). 명확화 질문에 대한 사용자
선택: (1) HAIR의 협업 구조를 게임화, (2) 웹 브라우저 게임, (3) 기획 +
동작하는 최소 프로토타입까지. 이 문서는 (1)(기획)을 담고, 실제 프로토타입은
별도 Artifact로 퍼블리시했다.

## 한 줄 컨셉

당신은 하루에 하나씩 들어오는 업무 요청(Brief)을 사람 또는 AI Agent에게
배정하고, 그 결과물의 품질(Gate 점수)을 보고 승인/반려를 결정하는
매니저다. 예산과 평판이 바닥나기 전에 N일을 버텨라 — **빠르고 싼 AI**와
**느리고 비싼 사람** 사이에서, 그리고 **의심스러운 결과물을 통과시킬지
반려할지** 사이에서 매 순간 판단해야 한다.

## HAIR 개념 → 게임 메커닉 매핑

실제 HAIR-Platform의 도메인 모델을 그대로 게임 규칙으로 바꿨다 — 새로운
개념을 만들지 않고, 이미 `docs/SPEC.md`·`docs/SCENARIOS.md`에 있는
구조를 "재미있게 체감할 수 있는 형태"로 옮긴 것이 이 게임의 핵심 아이디어다.

| HAIR 개념 | 게임 메커닉 |
|---|---|
| Brief(업무 요청) | 매일 하나씩 들어오는 "의뢰 카드"(필요 스킬·보상·마감일) |
| Task 분해 + 배정(F2, F5-F6) | 의뢰를 로스터(사람 2명 + AI Agent 3개) 중 하나에 배정 |
| 사람 vs AI Agent 트레이드오프 | 사람: 고정 일급, 느림(다음 날 완료), 안정적 / AI: 사용당 소액, 즉시 완료, 변동성 큼 |
| Gate A-G 자동 평가 | 배정 즉시 "Gate 판정"(스킬 매칭+신뢰도+무작위성 기반 0-100점) 애니메이션 |
| 승인/반려(F7) | Gate 점수를 보고 승인(보상 획득, 품질 나쁜데 승인하면 평판 손실)/반려(재시도, 마감일 소모) 결정 |
| 지식 색인(VectorDB 그라운딩, §41) | "정책 Agent"에 1회 투자하면 해당 스킬 성공률이 영구 상승(실제 기능의 "사전 투자→품질 향상" 개념을 그대로 수치화) |
| 자기승인 방지(ADR 3-A) | 게임에는 등장시키지 않음(1인 플레이 루프 단순화를 위한 의도적 생략, 아래 "범위 밖" 참고) |
| 예산/평판(Phase 5 대시보드의 cost/Gate 집계) | 게임의 패배 조건이자 스코어 — 예산 고갈 또는 평판 0 이하면 "해고" |

## 핵심 루프(1일 단위, 총 14일)

1. **의뢰 도착** — 필요 스킬 1개, 보상액, 마감(며칠 내)을 가진 Brief 카드 등장.
2. **배정** — 로스터에서 담당자 선택. 사람은 스태미나(하루 1건) 제한,
   AI는 무제한이지만 쓸 때마다 소액 비용.
3. **Gate 판정** — `성공확률 = 기본신뢰도 + 스킬매칭 보너스 + 무작위(-0.2~0.2)`
   를 0-100점으로 환산해 A-G 미니 배지로 보여준다(완전한 블랙박스가
   아니라 "왜 이 점수가 나왔는지" 분해해서 보여줘 전략적 판단이 가능하게 함).
4. **승인/반려** — 70점 이상 승인 권장(보상+평판), 50점 미만은 반려
   권장(승인 시 평판 손실), 50-70점은 의도적으로 애매하게 설계해
   "이번 의뢰의 위험을 감수할지" 자체가 플레이의 재미가 되게 한다.
5. **하루 마감** — 미해결 의뢰 마감일 감소(0 되면 위약 패널티), 사람
   인건비 차감.
6. **종료 조건** — 14일 생존 시 최종 스코어(예산+평판 가중치) 공개,
   예산<0 또는 평판≤0이면 조기 "해고" 엔딩.

## 기술 스택 및 실현 가능성 분석

**결론: 백엔드 전혀 없이, 단일 HTML 파일로 완전히 동작 가능하다.**

- **상태 관리**: 1인 플레이·세션 단위 플레이이므로 서버/DB가 필요 없다 —
  전부 브라우저 메모리(JS 변수)로 충분하다. HAIR 본체처럼 다중 사용자
  동시성·영속 저장·RBAC가 전혀 필요 없는 범위라, FastAPI+SQLite 스택을
  그대로 가져올 이유가 없다(오히려 복잡도만 늘어난다).
- **"AI 판정" 재현 방식**: 실제 LLM을 호출하지 않는다 — Gate 점수는
  스킬매칭·신뢰도·난수 기반의 결정론적 수식으로 **시뮬레이션**한다.
  진짜 HAIR의 Gate A-G 로직(agent_evaluation.py)과 똑같이 가지는 않지만,
  "AI 결과물은 품질이 들쑥날쑥하고 그걸 사람이 검증해야 한다"는 핵심
  긴장감은 동일하게 재현된다 — 실제 API 비용 없이 즉시 플레이 가능하다는
  게 오히려 이 범위에선 장점이다.
- **확장 여지(이번 범위 밖, 후속 검토용)**: 원한다면 HAIR 본체의
  `POST /api/tasks/{id}/execute-agent`를 실제로 호출해 "의뢰 설명문"을
  진짜 LLM이 생성하게 만들 수 있다(플레이 자체의 수치 로직은 그대로 두고
  플레이버 텍스트만 실제 AI로 대체) — 다만 이건 실제 과금과 API 키
  설정이 필요해 "동작 가능한 최소 프로토타입"의 범위에서 제외했다.
- **배포 형태**: Claude Artifact(독립 HTML)로 퍼블리시 — HAIR-Platform
  저장소와 코드 의존성이 없는 완전히 분리된 산출물이다(이 문서만 저장소에
  남긴다).

## 이번 프로토타입 범위 / 범위 밖

**포함**: 위 핵심 루프 전체(14일 생존전), 로스터 5명(사람 2+AI 3),
스킬 매칭 보너스, 지식 색인 업그레이드, 승인/반려 판단, 예산/평판
스코어링, 승리/패배 엔딩, 이벤트 로그.

**범위 밖(후속 과제)**: 멀티플레이·팀 Crew 그룹 실행 개념(이 게임은
1인 매니저 시점이라 "팀 전체 동시 실행" 메커닉은 다음 버전 후보),
자기승인 방지 같은 RBAC성 제약(1인 플레이에선 의미가 없어 의도적으로
뺐다), 실제 LLM 연동(위 "확장 여지" 참고), 세이브/로드(브라우저 새로고침
시 리셋 — 15분 내외의 한 판 길이라 영속 저장 없이도 괜찮다고 판단).
